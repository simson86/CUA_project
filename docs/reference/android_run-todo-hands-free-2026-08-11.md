## §1 핫워드가 안 되는 이유

- 일반 앱은 화면이 꺼진 상태에서 마이크를 상시 열어둘 수 없다.
- `AlwaysOnHotwordDetector` API 는 존재하지만 **기기의 DSP 하드웨어 + 기본 어시스턴트
  지위**가 전제라, 실질적으로 구글·삼성 기본 앱 몫이다.
- 우회하려면 마이크형 포그라운드 서비스로 상시 녹음 + 로컬 키워드 검출(Porcupine/Vosk 등)을
  돌려야 한다. 배터리 + 상시 알림 + Android 14 의 `FOREGROUND_SERVICE_MICROPHONE` 제약을
  전부 감수해야 하는 **별개 프로젝트**다.

→ **범위에서 뺀다.** "한 번 누르기"까지가 현실적 목표다.

## §2 트리거 후보

| 트리거 | 어디서 | 작업량 | 새 권한 |
|---|---|---|---|
| **접근성 플로팅 버튼** ★ | 모든 화면 | XML 1줄 + 콜백 1개 | 없음 |
| 우리 오버레이 버블 | 모든 화면 | 중 (드래그·위치 저장) | 없음 (`SYSTEM_ALERT_WINDOW` 보유) |
| 상시 알림 액션 버튼 | 알림창 | 소 | 없음 |
| 퀵 설정 타일 (`TileService`) | 알림창 | 소 | 없음 |
| **측면 버튼 두 번 누르기** ★ | 하드웨어 | **0줄** (삼성 설정에서 지정) | 없음 |
| 기본 어시스턴트 교체 | 홈 길게 | 대 (`VoiceInteractionService`) | 구글 어시스턴트를 대체함 |

### 추천: 접근성 플로팅 버튼

이 앱은 이미 접근성 서비스가 상시 떠 있으므로 가장 싸다.

```xml
<!-- res/xml/accessibility_service_config.xml — 현재 accessibilityFlags 자체가 없다 -->
android:accessibilityFlags="flagRequestAccessibilityButton"
```
```kotlin
// a11service.kt
override fun onAccessibilityButtonClicked() { /* 트리거 */ }
```

시스템이 그리는 버튼이라 우리 오버레이의 터치 가로채기 문제(`CLAUDE.md` 참조)가 없다.
제스처 내비게이션에선 화면에 떠 있는 접근성 버튼, 3버튼 내비에선 내비바 안에 나온다.

여기에 **측면 버튼 두 번 누르기**를 폰 설정에서 지정하면 코드 없이 하드웨어 트리거가 붙는다.

## §3 ★ 진짜 걸림돌은 트리거가 아니라 마이크다

**안드로이드 9부터 포그라운드가 아닌 앱은 마이크를 못 연다.**

- 접근성 서비스로 떠 있다는 것만으로는 마이크 접근권이 생기지 않는다.
- 마이크형 포그라운드 서비스로 우회하려 해도, **백그라운드에서 시작된 FGS 는 마이크를
  못 받는다**(API 30+)는 별도 제약에 다시 걸린다. 면제 조건이 있지만 기기·버전마다
  갈리는 영역이라 여기 기대면 안 된다.

### 정공법 — 투명 액티비티

```
[플로팅 버튼 탭] → VoiceTriggerActivity (투명 테마, 작은 카드만 그림)
                    ↳ 액티비티는 명백한 포그라운드 → 마이크 문제가 아예 없음
                    ↳ VoiceInput.kt 를 그대로 재사용 (이미 만들어 둠)
                  → 인식 완료 → finish() → 원래 앱 복귀 → a11service.runTask
```

"앱을 실행하는" 것은 맞지만, 사용자 눈엔 쓰던 앱 위에 작은 카드가 잠깐 뜨는 것뿐이다.
빅스비도 실제로 이렇게 동작한다. **권한도, 배터리도, 우회도 필요 없다.**

## §4 구현 전에 알아야 할 것

### (a) 첫 스크린샷이 "그때 보던 앱" 이 된다
버그가 아니라 이 방식의 **핵심 가치**다 — 카톡에서 "이 대화 캡처해서 보내줘"가 성립한다.
다만 `CuClient.system_prompt` 가 홈에서 시작하는 걸 전제하는지 확인해야 한다.
`list_apps`/`open_app` 안내는 "from anywhere, including from inside another app" 라고
이미 적혀 있으니 큰 수정은 없을 것으로 보이나, **실제로 돌려 보고 판단할 것.**

### (b) `finish()` 직후 바로 캡처하면 안 된다 ★
카드가 사라지는 애니메이션이 끝나기 전에 찍으면 모델이 우리 카드를 본다.
`CLAUDE.md` 「오버레이 제거는 비동기」와 **정확히 같은 함정**이다.
현재는 음성 인식 후 3초 카운트다운이 우연히 이걸 막아 주고 있다 —
카운트다운을 줄이거나 없애면 이 문제가 드러난다.

### (c) 설정값을 서비스가 직접 읽어야 한다
모델·사고수준·최대 턴은 지금 `MainActivity` 가 `SharedPreferences` 에서 읽어
`runTask` 에 넘긴다. 액티비티를 안 거치는 경로는 **서비스가 직접 읽어야** 하고,
안 그러면 소켓 `RUN` 처럼 조용히 기본값으로 돈다(이미 알려진 제약, `CLAUDE.md`).
→ 이 기회에 "설정 읽기"를 한 곳으로 모으면 소켓 `RUN` 의 제약도 같이 풀린다.

### (d) 안전
어디서든 한 번 눌러 실기기 조작이 시작되는 것이라 위험도가 올라간다.
**3초 카운트다운 + 취소는 반드시 유지한다.** 모델의 확인 카드는 비결정적이라
방어선으로 못 믿는다(`CLAUDE.md` Gotcha).

## §5 착수 순서 (제안)

1. 접근성 플로팅 버튼만 붙여 `onAccessibilityButtonClicked` 에서 토스트 — 트리거가
   실제로 오는지부터 확인
2. `VoiceTriggerActivity`(투명) 추가, `VoiceInput` 재사용, 인식만 되는지 확인
3. 설정 읽기를 서비스로 이동 (§4-c)
4. `finish()` → 캡처 사이 지연 확인 (§4-b)
5. 카톡 등 다른 앱에서 실제 작업 (§4-a)
